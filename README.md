# BookHaus

BookHaus is a cozy personal reading and library application for discovering books, building a personal library, organising user-defined shelves, tracking reading progress, journaling about books, saving favourite quotes and following reading goals and insights.

## Current status

Phase 2: backend architecture and project setup.

The Spring Boot backend scaffold and local PostgreSQL development environment are now in place. Feature implementation has not started yet.

## Local PostgreSQL setup

1. Copy `.env.example` to `.env`.
2. Change the example PostgreSQL password.
3. Start PostgreSQL from the repository root:

```bash
docker compose up -d postgres
```

4. Confirm the service is healthy:

```bash
docker compose ps
```

5. Stop it when needed:

```bash
docker compose down
```

Use `docker compose down -v` only when you intentionally want to remove the local database volume.

## Running the backend

The backend is a standard Maven project. Open the `backend` directory in an IDE with Java 21 and run `BookHausApplication` once PostgreSQL is available.

A Maven Wrapper is not included in this scaffold yet. It can be generated once Maven is available locally so that the wrapper files are generated by Maven rather than hand-maintained.

The development Spring profile imports the root `.env` file as a properties source and reads `DB_URL`, `DB_USERNAME` and `DB_PASSWORD` from it.

## Architecture principles

- Package code by feature as features are implemented.
- Create folders only when they contain real project code or configuration.
- Keep secrets out of source control.
- Use Flyway for database schema changes.
- Let JPA validate the schema rather than silently modify it.
- Add dependencies only when the relevant project phase requires them.
- Keep the functional application independent of the later immersive 3D room layer.
