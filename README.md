# BookHaus

BookHaus is a cozy personal reading and library application for discovering books, building a personal library, organising user-defined shelves, tracking reading progress, journaling about books, saving favourite quotes and following reading goals and insights.

## Current status

The Spring Boot backend scaffold and local PostgreSQL development environment are in place.

## Local PostgreSQL setup

1. Install PostgreSQL locally on Windows if it is not already installed.
2. Create a database named `bookhaus`.
3. Create a PostgreSQL user, or use an existing one, and grant it access to the `bookhaus` database.
4. Copy `.env.example` to `.env` in the repository root.
5. Set the local connection details in `.env`:

```properties
DB_URL=jdbc:postgresql://localhost:5432/bookhaus
DB_USERNAME=your_postgres_user
DB_PASSWORD=your_postgres_password
```

6. Start PostgreSQL normally through Windows. With the standard installer, start its Windows service from the Services app or with PostgreSQL's installed management tools.
7. Start the Spring Boot backend from the `backend` directory with Java 21 and Maven:

```powershell
mvn spring-boot:run
```

8. Flyway will connect through the Spring datasource and automatically apply the migrations in `backend/src/main/resources/db/migration/`.

## Running the backend

The backend is a standard Maven project. You can also open the `backend` directory in an IDE with Java 21 and run `BookHausApplication` once PostgreSQL is available.

A Maven Wrapper is not included. It can be generated once Maven is available locally so that the wrapper files are generated by Maven rather than hand-maintained.

The development Spring profile imports the root `.env` file as a properties source and reads `DB_URL`, `DB_USERNAME` and `DB_PASSWORD` from it. The `.env` file is ignored by Git.

## Architecture principles

- Package code by feature as features are implemented.
- Create folders only when they contain real project code or configuration.
- Keep secrets out of source control.
- Use Flyway for database schema changes.
- Let JPA validate the schema rather than silently modify it.
- Add dependencies only when the relevant project phase requires them.
- Keep the functional application independent of the later immersive 3D room layer.
